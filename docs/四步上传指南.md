# 四步上传指南（第一次做也能照着走）

> 目标：把 `projects\dsh-kb-lite` 这个本地仓库变成 `imaused/dsh-kb-lite`，并提交进
> [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 的收录列表。
>
> 全程只需要：一个浏览器 + 一个**普通 PowerShell 窗口**（不是 DSH 里的那个）。

---

## 准备：打开一个普通 PowerShell

按 `Win` 键，输入 `powershell`，回车。后面所有命令都在这个窗口里跑。

先确认 Git 在：

```powershell
git --version
```

---

## 第 1 步：在网页上建仓库（2 分钟）

1. 浏览器打开 <https://github.com/new>
2. **Repository name** 填：`dsh-kb-lite`
3. 选 **Public**
4. **下面的三个勾全部不要勾**（Add a README / .gitignore / license）——勾了会让后面的 `git push` 报错
5. 点 **Create repository**
6. 你会看到一个"快速开始"页面，先不用管它

> 如果 github.com 打不开/超时：这台机器到 GitHub 时通时断，刷新几次就行；
> 用 Edge 打开通常也能进去。

---

## 第 2 步：把代码推上去（3 条命令）

```powershell
cd C:\Users\DPXT\Documents\deepseek-harness\default-workspace\projects\dsh-kb-lite
git remote add origin https://github.com/imaused/dsh-kb-lite.git
git push -u origin master
```

执行第三条时会**弹出一个窗口**（Git 凭据管理器）→ 点 **Sign in with your browser** →
在浏览器里登录 GitHub（如果本来就是登录状态，点一下 **Authorize** 就好）。

看到类似下面这样就成功了：

```
 * [new branch]      master -> master
branch 'master' set up to track 'origin/master'.
```

刷新仓库页面 <https://github.com/imaused/dsh-kb-lite>，应该能看到 24 个文件和 5 条提交。

> **报错怎么办**
> - `could not read Username` / `Repository not found` → 仓库名拼错，或第 1 步没建成功
> - `Connection reset` / `timeout` → 网络抖动，把 `git push -u origin master` 再跑一次
> - `rejected ... (fetch first)` → 第 1 步不小心勾了 README，先跑 `git pull --rebase origin master` 再 push
> - 想确认远端状态：`git ls-remote origin`（能列出 `refs/heads/master` 就是成功了）

---

## 第 3 步：加 topic（1 分钟）

仓库主页右侧有个 **About** 区域，点它右上角的 **齿轮 ⚙**：

- **Topics** 框里输入：`dsh-plugin`
- 点 **Save changes**

> 这是收录 CI 的硬性检查项，漏了会被拒。

---

## 第 4 步：等满 1 天，然后提 PR（10 分钟）

**为什么等**：CI 会检查仓库创建时间 ≥ 1 天，今天提一定被拒。所以第 1–3 步做完就可以关电脑了，
明天再回来做这一步。

明天：

1. 打开 <https://github.com/awesome-dsh-plugin/awesome-dsh-plugin>
2. 点右上 **Fork** → **Create fork**（得到 `imaused/awesome-dsh-plugin`）
3. 在你的 fork 里点 **Add file → Create new file**
4. 文件名（注意是两个下划线）：

   ```
   data/plugins/imaused__dsh-kb-lite.yml
   ```

5. 内容贴这个（**一个字符都不要改**）：

   ```yaml
   url: https://github.com/imaused/dsh-kb-lite
   name: imaused/dsh-kb-lite
   category: memory
   description:
     en: 'Local knowledge base for DeepSeek Harness: five tools to ingest Markdown, plain text and PDF files, search them with BM25 or hybrid BM25 plus optional local embeddings, and answer with cited source passages. Runs offline with no database server.'
     zh: '本地知识库：五个工具，导入 Markdown、文本与 PDF，用 BM25 或 BM25 + 本地向量的混合检索查找，回答时带原文引用。离线运行，不需要数据库服务。'
   ```

6. 页面底部 **Commit changes**（提交到 `main` 就行）
7. 回到上游页面 <https://github.com/awesome-dsh-plugin/awesome-dsh-plugin>，会出现黄色横幅
   **Compare & pull request** → 点它
8. 标题填：`Add imaused/dsh-kb-lite`
   描述贴：

   ```
   Adds dsh-kb-lite: a host-only local knowledge base plugin.

   - Five tools: kb_ingest, kb_search, kb_ask, kb_stats, kb_clear
   - Ingests Markdown, plain text and PDF (PDF needs pymupdf)
   - BM25 with the Python standard library only; optional dense retrieval; RRF hybrid
   - Local index directory, no database server, the engine opens no sockets
   - Tested on Windows 11 with DSH 0.2.1-rc.1 / Node 24 / Python 3.14
   ```

9. 点 **Create pull request**

---

## 提交前自检（5 项全对才提）

- [ ] 仓库是 **Public**
- [ ] 仓库带 topic `dsh-plugin`
- [ ] 仓库创建**满 1 天**
- [ ] `package.json` 里有 `dsh.bundle`（已经有了，不用改）
- [ ] PR **只加了一个文件**（`data/plugins/imaused__dsh-kb-lite.yml`），没动别人的条目

---

## 之后会发生什么

- CI 依次检查：这个 PR 的条目数（≤3）→ 你仓库的 `dsh.bundle` → 仓库年龄 ≥1 天 → awesome-lint 与站点构建
- 失败会给出具体原因，**在同一个分支上改完再 push 即可**，不用重开 PR
- 通过后由维护者合并，网站和插件市场会自动重新生成
- 可选：以后想发 npm（`npm publish --access public`）能显示下载量，但要先 `npm login`；
  不发布也**不影响收录**
